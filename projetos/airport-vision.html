O problema

O sistema monitora as condições de um aeroporto com uma câmera PTZ, que gira e dá zoom sob comando, além de uma câmera fisheye apontada para o céu e dados meteorológicos. A versão original, em Python, deixava um Intel i9 com 80–90% de CPU ocupada o tempo todo. Isso exigia hardware caro e deixava pouca folga para o resto.

O que o sistema faz

  • A câmera PTZ percorre nove posições em loop. Em cada uma, mostra um preview ao vivo e guarda o último quadro.
  • Os nove quadros formam um mosaico 3×3, ao lado da câmera fisheye e dos dados meteorológicos.
  • Vários operadores podem assistir ao mesmo tempo. Só um controla a câmera; os outros podem pedir o controle, e ele passa automaticamente para o próximo se o operador atual sair.

A reescrita

Refiz o sistema em C++17 com Qt 6, separado em um servidor, que fala com as câmeras e monta o mosaico, e um cliente de visualização, ligados por WebSocket. O servidor transmite as imagens para todos os clientes a cerca de 30 quadros por segundo, e compila para Windows, Linux e macOS. Um serviço de watchdog acompanha o servidor e o reinicia se algo der errado.

Com isso, o uso de CPU caiu para cerca de 7%, agora num Intel i3. O sistema passou a rodar numa máquina bem mais barata, com folga.

O que aprendi

Medir antes de otimizar e escolher a ferramenta certa para cada parte. Python foi ótimo para validar a ideia, mas um serviço que processa vídeo sem parar, por anos, pede o controle de memória e de threads que C++ e Qt oferecem.

O código pertence à AMD Services e não é público. Esta página descreve apenas o comportamento do sistema e os resultados.

The problem

The system monitors conditions at an airport with a PTZ camera, which pans, tilts and zooms on command, plus a fisheye camera pointed at the sky and weather data. The original Python version kept an Intel i9 at 80–90% CPU all the time. That demanded expensive hardware and left little headroom for anything else.

What the system does

  • The PTZ camera loops through nine positions. At each one it shows a live preview and keeps the last frame.
  • The nine frames form a 3×3 mosaic, next to the fisheye camera and the weather data.
  • Several operators can watch at once. Only one controls the camera; the others can request control, and it passes to the next one automatically if the current operator leaves.

The rewrite

I rebuilt the system in C++17 with Qt 6, split into a server, which talks to the cameras and builds the mosaic, and a viewer client, connected over WebSocket. The server streams frames to every client at about 30 frames per second, and it builds for Windows, Linux and macOS. A watchdog service monitors the server and restarts it if something goes wrong.

CPU use dropped to about 7%, now on an Intel i3. The system moved to a much cheaper machine, with room to spare.

What I learned

Measure before optimizing, and pick the right tool for each part. Python was great for proving the idea, but a service that processes video nonstop, for years, calls for the control over memory and threads that C++ and Qt provide.

The code belongs to AMD Services and is not public. This page only describes the system's behavior and results.
